# Точки возврата

Если после новых правок что-то сломалось, можно вернуться к любой из точек ниже.
Самый простой способ: напиши Claude название точки, например **БЭКАП1**, и он вернёт код к этому состоянию.

---

## БЭКАП1 (тег `backup1`), 14.10.2026

**Что это.** Версия, собранная для релиза «для всех». Код этого состояния: коммит `629f1ea`.

**Что внутри и работает**
- Вкладки «Материалы» и «Рынок»: котировки по макету Figma, цены с сайта (с запасными источниками), Urals как средняя за месяц, тепловая карта, списки «Рост / Падение / По обороту», новости, окно котировки с графиком TradingView.
- Тикеры на аватарках акций, копирование тикера по долгому нажатию.
- Аналитика вкладки «Рынок» и скрипт заведения целей в Метрике (`scripts/metrika-setup-goals.mjs`).
- Коммиты Серёжи слиты: сборка через kaniko, активный раннер, права nginx, `healthz`, `robots.txt`.

**Заморожено (флажки `false` в `src/shared/config/features.ts`)**
- читалка постов внутри приложения (`POST_READER_ENABLED`)
- второе приложение «Работа не рабство» и меню по логотипу (`SECOND_APP_ENABLED`)
- вкладка «Календари» (`CALENDAR_TAB_ENABLED`)

**Известные проблемы на момент бэкапа**
- Новости из канала IF News на проде дают 504: из контейнера не открывается `t.me` (сеть сервера, ждём Серёжу).
- Блок «Популярные» на сайте, возможно, подгружается скриптом: тогда цены с сайта не подтянутся и будут запасные источники. Нужно проверить.

**Как вернуться**
1. Проще всего: написать Claude «БЭКАП1».
2. Вручную (история при этом не переписывается, возврат записывается новым коммитом):
   ```
   git fetch origin --tags
   git switch main
   git read-tree -u --reset backup1
   git commit -m "Возврат к БЭКАП1"
   git push origin main
   ```
   Затем на GitLab: `git fetch gitlab`, `git merge gitlab/main` (если у Серёжи есть новое) и `git push gitlab main`. Без `--force`.
3. Только посмотреть, не меняя ничего: `git switch --detach backup1` (вернуться: `git switch main`).

Тег есть только на GitHub: на GitLab его нет, чтобы не запустить лишний пайплайн.
